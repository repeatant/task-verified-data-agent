# 历史预设性质核验实验

本页记录移除 DB-GPT 运行路径之前的实验。反馈对照、消融及真实修复由当时的 DB-GPT 原生循环执行；这些成绩不属于当前 LangGraph 路径，也不用于计算动态核验的总体准确率。原始 JSON 证据保持不变。当前运行与评分入口见 [评测说明](../EVALUATION.md)。

旧版本的安装、模型调用和反馈实验 CLI 已从当前候选版移除。冻结查询挑战仍可用当前仓库的离线工具重放；保留的历史源码仅用于该回放，不是当前运行依赖。

## 完整与紧凑反例反馈

`legacy_v1` 对照使用相同模型、检测器、初始候选、生成种子及最多两轮原生尝试，比较完整和紧凑证据。16个人工候选×两个种子×两种反馈构成64个受控单元，另有3种自然任务×两种反馈，共70个单元。

其中8类错误能生成反例，形成16组有效配对：

- 完整反馈：修复14/16，输入28,017、输出3,599，总计31,616 Token。
- 紧凑反馈：修复14/16，输入26,044、输出3,377，总计29,421 Token。
- 诊断字符9,308→6,598，减少29.1%；实际输入Token减少7.0%，总Token减少6.9%。

全部受控单元中，两组各完成30/32；自然任务完整反馈3/3，紧凑反馈2/3。这些结果尚不能证明紧凑反馈的整体成功率不降。这些是固定schema开发任务，生成种子变化不构成新任务模板。

这是前一版反馈策略的实验，新版能力说明尚未重复原 16 组配对的完整对照；后续小子集实验见下节。数据见 [反馈配对结果](../../tests/fixtures/public_evidence/results.json)。

## 能力说明与分类反馈

模型在保留零值订单任务中使用了执行器不支持的CASE聚合。补充支持范围与分类修复指导后，同一个已知故障在两个生成种子下重复，旧反馈修复0/2，新反馈2/2；另8个数据条件的端到端任务8/8。

这轮早期实验将能力说明与错误指导组合，不能区分各自作用；后续已补下面的四组消融。同一故障的两次重复不等于两种独立问题。示例见 [旧反馈轨迹](../../tests/fixtures/public_evidence/legacy_failure.json) 与 [能力反馈轨迹](../../tests/fixtures/public_evidence/capability_repair.json)。

## 反馈消融与状态升级

后续开发实验固定 `d10`、`d11` 两条受控候选及 `d03` 一个自然任务，生成种子为 53，最多 3 个原生尝试步骤。受控首轮注入不算 HTTP；生成种子也不是模型采样种子。四组都保留基础 `supported_sql`，比较额外完整执行契约与分类指导的边际作用。

12 个消融单元中，8 个受控单元全部修复：

- `d10` 的基础反馈经过 WHERE → CASE → JOIN ON，两次真实修复调用才成功，消耗 4,175 Token。仅完整契约、仅分类指导、两者组合都只需一次修复调用，分别为 2,195、2,068、2,369 Token。
- `d11` 四组都一次修复成功，分别为 1,707、1,999、1,739、2,009 Token。该错误码没有专门分类指导，本题不能独立证明分类指导有效；完整契约在这里增加了输入开销。

自然 `d03` 中，三个增强组各用两次 HTTP 后正确。基础反馈组首个响应达到 900 输出 Token 上限，被标为截断操作失败，没有进入 Action；它不能被归为 SQL 语义错误。原停止报告保持不变，仅核清完整用量后补执行此前未运行的 `capability_only` 单元。合并结果保留该失败，最终为 11/12 正确、1 次操作失败，消耗 16 次实际 HTTP、32,650 Token。

随后使用相同三个任务比较完整、紧凑和自适应策略，均提供完整契约与分类指导，每组均 3/3 正确、使用 4 次 HTTP。三组总 Token 分别为 9,343、8,614、8,994。自适应组没有出现连续失败，升级触发及后续完整证据消费均为 0；因此本轮没有验证升级策略的效果。重复错误的三步离线脚本另外验证了升级与回归接线，但不计入真实模型成绩。

这两项实验只有三个已知开发任务，不足以确定稳定的主效应、交互效应或泛化提升。执行顺序按任务轮换，各组采用相同尝试上限。核验器、模型、900 输出上限及运行时源码在初次实验与补充执行之间保持一致；仅实验续账与补齐入口扩展，其版本摘要分别保留。

策略与指标见 [反馈机制](../FEEDBACK.md)，公开投影见 [消融与策略结果](../../tests/fixtures/public_evidence/feedback_experiments.json)，脚本升级过程见 [离线升级轨迹](../../tests/fixtures/public_evidence/adaptive_replay.json)。

## 独立冻结查询挑战

在读取新题之前冻结实现，由独立上下文AI代理按公开契约设计24项，另一个代理用Python与SQLite复核数据和标签。题目包含8条合法、10条语义错误和6条超范围候选；4个自然任务在评分前预选。

初次结果为21/24：8条合法全部接受，6条超范围全部拒绝，3条语义错误被放行。漏洞分别是未声明渠道限制、误将NULL归并当作过滤，以及LEFT JOIN产生无有效明细的零额组。预选自然任务4/4通过，没有自然产生这3种错误。

检查增加任务范围、匹配见证与分组成员约束后，原24项转为已知回归，24/24通过。3条原错误候选作为明确注入首轮，再由真实模型修复3/3。修复后同集成绩不计为新的留出结果。

题目及原始实现见 [冻结挑战](../../tests/fixtures/independent_holdout/frozen_challenges.json) 与 [结果摘要](../../tests/fixtures/public_evidence/independent_challenge_results.json)。这一验证采用合成数据和独立AI上下文，不是外部人工测评或公开基准。

## 历史测试口径

早期源码整理时，独立原生依赖环境通过 842 项测试；96 组新旧实现对照的反馈与发布结果一致。后续 LangGraph 联调时，基础环境通过 767 项、跳过 12 项可选测试；原生环境通过 932 项、跳过 2 个 LangGraph 专属模块，并排除三个未安装的早期服务测试文件。覆盖有重叠，不能合并为总测试量，也不能作为当前候选版的验证结果。

当时静态基线已拒绝开发集全部 11 个已知错误候选；独立挑战发现的 3 个漏洞通过范围与外连接语义检查修复。因此预设性质实验尚无动态新增检出收益的证据，已测收益集中在诊断重放与反馈压缩。
