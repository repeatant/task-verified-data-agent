# Expanded evaluation protocol

Status: development and implementation validation. Formal test results are not
available until the frozen run completes. Never substitute this plan for results.

## Questions

1. Does a bounded verification-and-repair agent deliver more correct SQL than
   direct generation, execution-feedback self-review, or one-reference repair?
2. Does it protect correct SQL when the reference or auditor is wrong?
3. Which effects are attributable to search, blind context and evidence-based
   authorization? A refusal counts as non-delivery, not a successful repair.

## Data

The pinned BIRD Mini-Dev contains 500 questions. Static support auditing selects
247 candidates from eight databases. The main test contains 100 questions from
six databases. Twenty development questions use two different databases.
The complete eligibility list, rejected reasons, original SQLite digests and
upstream annotation revision are recorded before model outcomes are inspected.
See [public data support](PUBLIC_DATA_SUPPORT.md).

The controlled set has 100 trajectories: 20 task/fault parent combinations,
five initial conditions, ten error mechanisms, but only **18 distinct original
requirements**. Upper/lower boundary faults share two original questions.
Statistics cluster by original requirement, not by trajectory or generated row.
Each trajectory is scored on the source plus 24 held-out datasets, using a third
handwritten arithmetic oracle verified against authored SQL and reference DSL.
These generated tasks are not claimed to be an independent public benchmark.

Conditions are SQL wrong, first reference wrong, both correlated-wrong, injected
auditor wrong, and initial pair correct. Except for the injected-auditor condition,
the auditor is generated by the real model: the condition describes the initial
pair, not a guarantee that every other component remains correct.

## Model visibility and scoring

Initial writer/reference contexts see task, complete supported schema, key/type
metadata, public evidence, and a question-independent bounded excerpt from the
official column dictionary. Excerpts round-robin tables, prioritize value codes,
and disclose omissions; they are not selected using gold SQL. They do not see gold SQL, expected results, fault
labels, the other program or held-out test inputs. Initial programs are cached
once and reused across methods; no best-of-N selection occurs.

Agent executions use an explicitly bounded, key-consistent preview (two seed
rows per table, then actual referenced parent rows; at most 50 rows per table,
500 total rows and 12,000 characters) plus model/search-generated fixtures.
Original SQLite databases remain unchanged. Final SQL is scored against official
gold on the **complete original database**, using BIRD set-based EX. Duplicate-row
and order comparisons are reported separately. Preview agreement does not imply
full-database correctness. Runtime preview limits and the scorer's ten-second
limit are separate; resource failures never justify post-result sample removal.
Only declared PK/FK/type constraints are represented in generated fixtures;
unmodeled CHECK/UNIQUE/business invariants remain a limitation.

## Compared protocols

- `direct`: one initial SQL and its execution gate. This is a lower-cost reference.
- `self_repair`: inspect original task plus execution feedback, recheck even
  executable SQL, at most three revision calls; no reference calculation.
- `two_way`: immutable first reference, executable probes, pairwise search,
  candidate-only repair and final replay. This is a complete competing protocol,
  not a fake third vote or a perfectly isolated auditor-only intervention.
- `full`: blind additional calculation, evidence-based change authorization,
  bounded reference/candidate revision and final replay.

All four run on all main cases. A seeded, response-independent subset of 20
public questions and eight controlled parents (40 trajectories) also runs:

- `no_search`: no Hypothesis calls; keep model-generated probes.
- `visible_audit`: same role/model/output contract, additionally exposes candidate,
  first reference and observed results; no writer reasoning history.
- `model_authorization`: allow the model to select a change target without the
  pair-agreement prerequisite. Keep validated citations/check IDs, read-only SQL,
  restricted reference interpreter, resource limits and final replay.

The test therefore plans 980 method trajectories. Calls and tokens are not
assumed equal merely because turn ceilings match; report measured cold-start
effective cost and actual deduplicated shared-cache cost separately.

A predeclared stability subset contains five public questions and one controlled
trajectory from each condition, sampled before test outcomes. Two fresh full
protocol repetitions add 20 trajectories; their variability is reported separately
and never increases the primary independent sample count.

## Execution and evidence

Temperature 0; output cap 1,800 tokens; up to three candidate/review turns;
40 search examples; twelve paid requests after shared initialization per cell.
Four serialized accounting lanes run concurrently. Code, prompt, data/split and
parameters are hash-bound for each named version. Each raw initial/cell record is
persisted before the next operation; failed trials stay in the denominator.
Only fully accounted output truncation may continue to the next trajectory,
with an immutable incident and full-ledger continuation. Unknown accounting or
unexpected persistence failures stop the campaign; no hidden transport retries.

The user explicitly approved a cumulative CNY 60 ceiling on 2026-11-07. Earlier
CNY 5 + CNY 3 allocations remain preserved. New lanes allocate CNY 52 total;
conservative reservations are never refunded. Cost estimates are not cloud bills.

## Analysis and changes

Report correct delivery, wrong release, correct-SQL damage, correct-task rejection,
candidate/reference/auditor correctness where independently scorable, calls,
tokens, latency and estimated cost. Keep public and controlled populations
separate. Use paired requirement-cluster bootstrap (2,000 repetitions, seed
20261107), and show database/family breakdowns. Confidence intervals describe
this selected sample; they do not establish universal correctness.

Development failures may change interfaces/prompts before the main freeze.
The first development version showed that requiring full relational fixtures
inside every initial reference response often exhausted the output/format budget.
Generic tasks therefore explicitly permit an initial reference with no invented
fixtures: the bound preview still executes, search still runs, and later model
probes still require valid data. This option does not apply to controlled legacy
tasks and never skips the final replay.
After inspecting the formal test, further fixes get a new version and retain the
first scores. Re-running those same questions is diagnostic, not an untouched
test. A new held-out confirmation set must be selected before evaluating fixes.

Deferred: BIRD-CRITIC's official gold/tests require separate access; no invented
gold or claimed CRITIC result is included. The historical 29.1% diagnostic-character
reduction belongs to an earlier experiment, not this campaign.
