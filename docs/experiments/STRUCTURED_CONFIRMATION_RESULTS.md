## 设计与边界

本实验使用主实验结果分析前预先选定的 40 条新问题，与主实验 100 题和开发
20 题均不重叠。它们来自四个**已使用过的 schema**：`california_schools` 18 题、
`card_games` 18 题、`codebase_community` 2 题、`toxicology` 2 题。
这是既有数据库内的新题确认，不是新数据库测试，分布也不均衡。

每题先使用一次普通 JSON 模式生成 SQL，两种模式严格共享该 SQL。随后每种
模式独立生成首参考，再执行相同的完整核验协议。题目、提示词、温度、输出
上限、执行器、评分器及搜索/复核策略相同；计划内变量为输出格式，包含其
必要的 Schema 输入计费及检查点身份区分。首参考不是同一份文本，有限样本的
生成波动仍存在。

模型为 `qwen3.8-flash`、温度 0、单次最多 1,800 Token；首参考最多三次生成/
格式修复，后续最多十二次调用，最多三次候选尝试、三轮复核、四十个搜索样本。
Writer 使用 SQL 动作 Schema；Reviewer 和 Auditor 使用核验动作 Schema。
本地 DSL、引用、测试数据和业务证据校验继续执行，Provider Schema 不能替代它们。

首次兼容性 smoke test 单独记录。失败轨迹不重抽，不根据这批确认题修改协议，
不将同题改进后的结果覆盖本轮。运行标识为 `structured-confirmation-v2`；v2
仅重新绑定经审核的预算 driver，题目、运行逻辑和提示词与冻结选题保持一致。

## 结果与区间

每组分母都是相同的 40 题：

- `json_object`：**正确交付 1、错误交付 0、未交付 39**。正确交付率 2.5%，
  经验 95% 区间为 0%–7.5%。
- `strict_schema`：**正确交付 0、错误交付 2、未交付 38**。错误交付率 5%，
  经验区间为 0%–12.5%。

按“严格模式减普通模式”，正确交付差为 **−2.5 个百分点**，配对 95% 区间
`[-7.5,0]`；错误交付差为 **+5 个百分点**，区间 `[0,12.5]`。公开 JSON 中沿用
评分器的反向约定 `json_object − strict_schema`，读数时必须区分符号。
区间由固定种子、2,000 次按问题分簇的配对 bootstrap 得到，未作多重比较校正。

普通模式的一条正确交付来自 `card_games`；严格模式的两条错误交付分别来自
`california_schools`、`card_games`。另外两个数据库两种模式均未交付正确 SQL。
共享初始 SQL 有 11/40 正确，其中普通模式拒绝 10/11，严格模式拒绝 11/11。

普通模式零错放只对应交付了一条正确结果，不能称为高可靠性。零事件产生的
经验区间 `[0,0]` 也不是总体错误风险上界为零。样本较小、正确交付接近零，
本轮只能否定“已有证据支持默认启用”的说法，不能证明 Schema 在所有场景无用。

## 格式接受率与语义正确性

两组首参考接受数均为 **28/40**。累计参考验证失败为普通模式 62 次、严格
模式 65 次；这是生成/修复尝试的计数，一道题可以失败多次，不是失败题数。

这里的“接受”同时要求动作、受限 DSL 及测试数据满足本地契约，**不是纯 JSON
格式合规率，更不是参考计算正确率**。本轮没有观察到这项综合接受数的提升。
严格模式仍不能保证 Python/DSL 中的调用合法、需求引文准确、参考计算正确，
也不能为当前协议补出“修复错误 Auditor”的决策出口。

因此保留可选适配器用于进一步研究输出约束，但不改默认模式，不把这轮实验
写成语义提升，也不以更少的结构错误替代端到端交付指标。

## 延迟、请求与费用

本轮每方法计时包含**首参考生成加后续核验**，排除共享初始 SQL 生成：

- 普通模式中位数 20.62 秒，P95 45.90 秒。
- 严格模式中位数 22.97 秒，P95 43.88 秒。

这与此前主实验“排除共享 SQL 和首参考的后初始化计时”不同，不能直接横向
相减。原始聚合器的通用字段名不改变本轮实际计时范围；公开摘要已明确重命名为
`reference_plus_verification_seconds`。

本阶段包含 smoke 的实际去重请求为 **386 次**、**1,788,759 Token**，usage
完整。输入 1,660,343、输出 128,416 Token，按冻结标价估算约 **¥1.6749976**。
每方法冷启动等效请求分别为 207 和 218 次，包含各自所需的共享 SQL；两者
不能直接相加当实际请求数或费用。
