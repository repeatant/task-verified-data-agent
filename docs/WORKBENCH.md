# DataVerify 本地 SQL 核验工作台

在订单示例库或公开企鹅观测数据上提出统计问题。可以先查看每张表的五条原始样本和统计口径，提交后查看结果、SQL、执行证据和修订记录。通过核验的结果支持下载 CSV。

## 启动

体验包已包含构建好的网页。解压到可写目录，首次启动只需要 Python 3.12 和网络连接，用于安装 Python 依赖。从 Git 源码启动或修改前端后重新构建，还需 Node.js 22.12 或更高版本。启动器优先使用已有的 pnpm，也可通过 Node.js 自带的 npm 调用 pnpm 10。在解压或克隆得到的项目根目录运行以下命令。

```powershell
py -3.12 tools/start_workbench.py
```

如果 Python 3.12 的命令名是 `python` 或 `python3.12`，用该命令替换 `py -3.12`。启动器在仓库内建立独立环境 `.venv-workbench/`，按锁安装依赖并构建前端。终端出现 Uvicorn 的监听地址后，打开[本机工作台](http://127.0.0.1:8765/)。按 Ctrl+C 结束。再次执行相同命令会复用环境和页面。准备完成后，离线示例与历史回放可断网运行，无需模型密钥。仅准备环境可添加 `--prepare-only`，更换端口可添加 `--port 8770`。

下文独立运行的 `python -m dataverify...` 命令应使用此环境的解释器。Windows 对应 `.\.venv-workbench\Scripts\python.exe`，Linux 和 macOS 对应 `.venv-workbench/bin/python`。前端开发可额外运行 `pnpm --dir frontend dev`，Vite 会将任务请求代理到同一后端。任务库和动作记录保存在 `artifacts/workbench/`。

## 演示

- **离线执行**。选择“统计所有已结算明细的净金额，退款按负值计入。”示例库中的 100、100、-25、90 分合计 265 分。离线示例提供预写的模型动作，运行时执行 LangGraph、SQL 和核验器。
- **公开数据**。进入 [Palmer Penguins 工作区](http://127.0.0.1:8765/?source=palmer-penguins)，展开原始样本，再选“分别统计每个物种的观测记录数，按物种名称升序排列。”整库三组结果分别为 152、68、124。选择“统计可用于分析的观测记录数。”可以先澄清是统计全部观测，还是只统计有体重值的记录。页面保留了原始数据及许可的链接。
- **调查分歧**。选“统计所有已结算明细条数，相同金额的不同明细分别计数。”展开执行证据，观察去重计数和明细计数的差异，再查看 SQL 与参考程序的修改。最终得到 4 条。
- **补充口径**。选“统计已结算的数量。”填写“按订单数”得到 2，填写“按明细条数”得到 4。回答澄清会创建关联版本，原问题和上一次处置可追溯。
- **历史模型回放**。左侧“等额明细被重复去重”绑定另一份历史合成数据。候选、参考、独立核算初始为 5、5、6，最终交付 6。回放 JSON 保留实验标识与原记录摘要。
- **真实问数**。选择“千问实时”，用自己的话提出当前 schema 能表达的问题。模型生成与数据范围均有约束，页面会如实显示完成、澄清、证据不足或中断。凭据通过服务端环境变量配置，已有开发环境沿用历史累计账本。

## 调用与恢复

在左侧选择[同一条正确 SQL 为何被拒](http://127.0.0.1:8765/#/replay/split-signoff)，可以看到旧协议把真正的核验记录和调查编号放在一起时拒绝了交付。分栏后，同一个当前版本检查支持签核，调查 `q0002` 进入辅助说明，最终在完整示例库上执行得到 669。网页读取两次历史千问调用，无需额外付费。

离线的明细计数示例默认展示分栏。千问实时模式可显式勾选“试用分栏签核”，CLI 对应 `ask --split-finish-evidence`。此设置与“分歧时允许额外查询”独立，随任务及补充口径保存。两份参考程序与 SQL 可能有共同误解，一致性结论只覆盖实际检查过的输入。[真实对照与错误案例](experiments/SPLIT_SIGNOFF_20261121.md)

新检出仓库首次启用千问时，先配置标准按量 API 环境变量（见仓库的 `.env.example`），再显式运行 `python -m dataverify.workbench.live_budget --limit-cny 2` 设定本地累计预算。初始化命令仅适用于没有既有研究账本的新环境。密钥由服务端读取。

实时任务详情显示该任务累计的千问请求尝试次数和供应商回报的 token 用量，包括恢复前的调用。用量缺失会单独标注。离线示例使用预写的模型动作，浏览历史回放仅从本机读取已有结果。这两种操作都不会新增模型请求。

实时模式默认执行候选 SQL、样本核验与最终查询。若希望诊断环节在出现分歧时另行查库取证，提交前勾选“分歧时允许额外查询”。选择随任务及澄清版本保存。六条开发轨迹中，额外查询消耗了有限动作次数，未提高正确交付数。[配对实验及局限](experiments/QUERY_ABLATION_20261121.md)

`POST /api/workbench/runs` 接收 `question`、`source_id` 和 `mode`。同一提交重试时可复用 UUID 型 `Idempotency-Key`。使用返回的 ID 调用 `GET /api/workbench/runs/{id}`。命令行与网页访问同一个任务库：

```powershell
python -m dataverify.workbench ask "统计所有已结算明细的净金额，退款按负值计入。"
python -m dataverify.workbench sources
python -m dataverify.workbench ask --source palmer-penguins "统计有体重测量值的观测记录数。"
python -m dataverify.workbench get <run_id>
```

服务重启时，排队任务继续执行，运行中的任务标为中断；查看任务后可以主动恢复。动态生成阶段使用 SQLite 检查点，分歧调查从已持久化的模型回复重建版本及观察，重新执行只读查询。任务或输入指纹变化时停止重放。上次付费请求结果未知时保留中断状态，需核对账本。清空页面或刷新浏览器不会重发一次模型请求。

## 验收

打开[公开数据千问回放](http://127.0.0.1:8765/?source=palmer-penguins#/replay/penguins-2009)可查看一次自定义提问。原任务用了 5 次千问请求，返回 2009 年共 120 条观测；按年份独立筛选原 CSV 也得到 120 条。回放只读取已保存的结果。工作台对合计不超过 500 行的登记库做整库复核，按含重复行的结果集比较；用户要求的排序仍应单独检查。

任务详情中的“未通过的动作”保留具体拒绝原因。例如，模型提交最终 SQL 时，如果把普通调查查询也列为交付签核证据，工作台会显示是哪条证据规则拦住了这次交付。仅在实验中启用过的“末轮只做决策”未达到采用门槛。[策略实测与单步对照](experiments/TERMINAL_DECISION_20261121.md)

先构建前端并启动本地服务，安装 Chrome 后运行 `pnpm --dir frontend run test:e2e`。浏览器测试检查提交、刷新、澄清、任务版本链接、真实 SQL 结果、修订和历史回放。后端测试用 `python -m pytest -q tests -k workbench`。本地示例和回放均可离线使用。
